# Источники AnimePlay 0.1.6-dev

## Каталог

- AniList GraphQL: https://anilist.gitbook.io/anilist-apiv2-docs — названия, описания, постеры, жанры, рейтинги и данные о сезонах. Не является источником видеосерий.

## Русская озвучка — AniLibria / AniLiberty

- API V1: https://anilibria.top/api/docs/v1
- Поиск релизов, получение карточки релиза и получение HLS-ссылок эпизодов выполняются через документированные методы API V1.
- Приложение не обходит блокировку региона или правообладателя. Если API отмечает ограничение, приложение не воспроизводит такой релиз.
- HLS доступен для потокового воспроизведения в Media3; офлайн-загрузка HLS не реализована.
- Использование открытого API не означает, что AnimePlay — официальное приложение сервиса, или автоматически предоставляет лицензию на каждое произведение.

## Студийная Банда / Studio Band

- Официальный сайт: https://www.studiobandme.ru/
- В приложении доступен переход на сайт студии. Публично документированный API/SDK для встраивания каталога и плеера не обнаружен в рамках подготовки этой версии. Извлечение/копирование видеопотоков не выполняется.
- Для нативной интеграции потребуется получить от студии API/SDK, правила использования и согласие на встраивание.

## Пользовательские источники

- Пользователь может добавить собственный HTTPS URL и субтитры, если имеет право на воспроизведение и сохранение материала.
- Загрузка в этой версии ограничена прямыми MP4/M4V/WebM URL. HLS/DASH загрузка офлайн не поддерживается.

## Публикация

Перед публичным выпуском проверьте условия каждого источника, права на видео/постеры/озвучки, требования к атрибуции, возрастные ограничения, правила магазинов и политику конфиденциальности.


## Расписание серий (добавлено в 0.1.4)

- Используется официальный GraphQL endpoint AniList: `https://graphql.anilist.co`.
- Календарь запрашивает опубликованные будущие элементы `Page.airingSchedules` в пределах 21 дня, с пагинацией (до пяти страниц по 50 записей).
- Применяются `notYetAired: true`, `airingAt_greater`, `airingAt_lesser`, `sort: TIME`.
- Время Unix конвертируется в локальный часовой пояс устройства. Расписание обновляется по кнопке; даты могут меняться у правообладателей/телеканалов.
- Источник предоставляет информацию о запланированном эфире, а не ссылку на видео.

## Отзывы

- Отзывы и оценки хранятся в SharedPreferences на устройстве пользователя.
- Межпользовательская публикация не включена: для неё необходим backend, аккаунты, политика хранения данных и модерация.

## Kitsu: персонажи для аватара (0.1.5–0.1.6-dev)

- API base: `https://kitsu.io/api/edge`.
- Поиск аниме: `GET /anime?filter[text]=...&page[limit]=12`.
- Персонажи тайтла: relationship `GET /anime/{id}/characters?include=character&page[limit]=20&page[offset]=...`; до трёх страниц загружаются последовательно (максимум 60 персонажей). Обработчик читает included character resources и использует только HTTPS-портреты с `media.kitsu.io`. В интерфейсе можно отфильтровать персонажей по имени.
- В локальном профиле сохраняется ссылка и подпись персонажа; изображение не встраивается в APK и загружается с сервера источника.
- Ограничение: документация Kitsu подтверждает API и relationship-модель, но сама по себе не является лицензией на перераспространение изображений персонажей. Перед публикацией потребуется отдельная проверка условий Kitsu и прав правообладателей/загрузчиков. Если источник недоступен, профиль показывает нейтральную заглушку, а не подменяет её выдуманным персонажем.

## Внутренние списки просмотра

Списки «Смотрю», «Просмотрено», «В планах», «Отложено», «Брошено» сохраняются локально через SharedPreferences. В профиле можно открыть каждый список, просмотреть постеры/названия и убрать запись. Это не облачная социальная функция; синхронизация требует аккаунта и backend.


## Ограничение AniList перед публикацией

Действующие официальные условия AniList API запрещают использовать API в конкурирующих, некомплементарных сервисах той же природы, включая аниме/манга-трекеры и списки. Поскольку AnimePlay планирует собственные списки просмотра, публичный релиз на этой интеграции нельзя считать согласованным. Нужно получить разрешение AniList или заменить источник метаданных и расписания на подходящий по условиям.


## AnimePlay 0.1.6-dev — интерфейс профиля

- Удалены универсальные сгенерированные портреты-заглушки из ресурсов приложения.
- Пользователь ищет аниме через Kitsu, затем выбирает доступного персонажа из выбранного тайтла.
- Выбранный персонаж и рамка остаются локальными настройками приложения.
- Все пять списков просмотра открываются отдельно из профиля; тайтл можно убрать из списка.
- Пока нет аккаунтов, облачной синхронизации, общего профиля и общего сообщества.

## Правовые ограничения

Kitsu API docs подтверждают публичные GET-endpoints и JSON:API-модель, но не дают автоматически права на повторное распространение картинок персонажей. Нужно отдельно проверить лицензию API, права на изображения, атрибуцию и разрешение на коммерческое использование перед публикацией. Официальная документация: https://hummingbird-me.github.io/api-docs/ .

AniList Terms of Use: https://docs.anilist.co/guide/terms-of-use . Текущий прототип всё ещё использует AniList для основного каталога и расписания; для публичного релиза требуется разрешение либо замена источника.
